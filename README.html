usdm-acdc-in-practice

USDM v4.0 and the CDISC AC/DC framework — BC to DC to AC — applied end to end on a simulated Phase 3 oncology trial.

What this is

CDISC’s cdisc-org/analysis-concepts implements the AC/DC framework: an Observation / Derivation / Analysis Concept model, 60 methods, a transformation library, an eSAP model and a working browser-based builder with in-browser R execution.

This repository does not reimplement any of that. It takes three real endpoints of graded complexity through the full chain and records what the process actually costs — what is automated, what a human authors, and where it strains.

The source study is TORIVA-LUNG 301, a simulated Phase 3 NSCLC trial with a fictional sponsor. It was chosen because it is the only available source where protocol, SAP, programming specs and built ADaM all exist, are internally consistent, and carry no confidentiality constraint. That last point matters: without built ADaM there is no ground truth, and without ground truth the exercise only demonstrates internal coherence.

Findings

These came out of applying the framework, and are the most reusable part of this repository. Each is written up in docs/findings/, with the commands and output that establish it.

Every finding was re-verified against the pinned upstream commit before being written up. Two of the five original findings did not survive that check, and one was retired outright — including one of the two that was slated to be filed as an upstream issue. See docs/method.md for why that step exists.

ID Claim Status at 739344c
F01 No time-to-event derivation transformations exist Confirmed
F02 The censoring statistical role is declared and unused Corrected
F03 Chain position carries meaning that individual entries do not Confirmed, stronger
F04 The BC joint is annotated, not resolved Retired
F05 No study-level view exists Restated
F06 No general predicate exists over more than one variable New

F01 — No time-to-event derivation transformations exist. Confirmed. The strings CNSR, censor and AVAL appear nowhere in the transformation library. T.OS_LogRank binds time and event as inputs, so the survival chain begins already derived. The gap is wider than “author three or four new T. entries”, because of F06 and because each derivation transformation emits a single output measure while a TTE derivation must emit four coordinated ones.

F02 — Time and event are indistinguishable in method metadata. The premise was wrong. There is no censoring value in StatisticalRole and there never has been — git log -S over the schema returns nothing. The role actually declared and unused is offset. The consequence stands and is the part that matters: M.KaplanMeier, M.CoxPH and M.LogRankTest each declare time and event as two response roles, so any signature over input roles treats them as interchangeable.

F03 — Chain position carries meaning that individual entries do not. Confirmed, and stronger than stated. T.ADAS_SumAvailableScores and T.ADAS_MissingScaleCapacity differ in exactly one field: the free-text note on an input binding. Every machine-readable field is identical, so no signature over structured fields can separate them.

F04 — The BC joint is annotated, not resolved. Retired. In the worked derivation scenario all five Measure terminals carry 11 linkedBCIds each. The four terminals without links are dimensions — Subject, Parameter, Treatment, Visit — which have no BC to link to. The endpoint-level linkedBCIds is empty, which is where the original reading came from; linkage lives at terminal level, which is the right place for it.

F05 — No analysis-coverage view exists. Restated. js/views/study-overview.js does exist and does show objectives and endpoints. What it carries is a checkbox per endpoint, feeding endpoint selection into the eSAP builder. It holds no authoring state: no chain status, no shared derivations, no coverage. The gap is narrower than claimed and sharper.

F06 — No general predicate exists over more than one variable. New, and it blocks the complex tier. M.ConditionalValue is not a general conditional — its predicate is hardwired to IF(IS_NA(value), alternate, base). M.ThresholdCompare compares one input to a constant. M.Categorization takes free-text conditions over a single value input. So the specification’s hypothesis that the FDA 2018 censoring hierarchy composes as nested M.ConditionalValue over M.RecordSelection is false on paper, before any authoring.

Issues 1, 2 and 3 are proposed upstream. See docs/findings/upstream-issues.md.

The endpoint ladder

Tier Endpoint Estimand Expectation
Simple Laboratory change from baseline — Works with no new authoring. T.BaselineSelection and T.ChangeFromBaseline exist
Moderate Objective response rate E3 / E3a Analysis side exists. Confirmed BOR derivation is the work
Complex Progression-free survival E2 / E2a Analysis side exists, derivation does not. Finds the limit

The simple tier matters because it is shallow — it shows the framework does not impose machinery where none is needed. The complex tier is a stress test, and a negative result there is a finding rather than a failure.

The CDISC Pilot’s ADAS-Cog endpoint is retained as a control, since it is already worked upstream. When something breaks, it distinguishes a broken flow from a broken endpoint.

Out of scope: adverse events (a different shape — event observations, counts, OCCDS rather than BDS) and the remaining five ADTTE parameters.

Method

Each endpoint follows the same four steps, and the directory structure enforces the order:

  1. mapping.md — map the chain on paper against the SAP text, before opening the builder. If it does not compose on paper, that is the finding. Doing this after authoring makes a negative result uninterpretable.
  2. chain.json — the authored eSAP scenario.
  3. comparison.md — output against the built ADaM, with each divergence classified as model limitation, specification ambiguity, or authoring error.
  4. log.md — elapsed time and every point where a decision was needed.

Step 4 is the point. One ADAS-Cog endpoint took nine nested derivation steps, manually assembled. A real study has ten to fifty analysis-relevant endpoints. Whether that scales is an empirical question, and the authoring cost per tier is the answer.

Two deliberate choices:

Upstream is a pinned submodule, not a copy. Copying is easier in the moment and strands the repository on a divergent snapshot within two releases.

TORIVA is referenced by commit, not vendored. It is 81 MB and read-only input. study/source-refs.md pins the commit and points at the specific SAP sections and spec files used, so the work is reproducible without duplicating the study.
